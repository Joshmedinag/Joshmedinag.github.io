01 / LIGHTING TD PIPELINE

FarmFlow.

A production-minded Maya and Arnold pipeline that validates scenes before render, verifies every EXR and leaves a traceable handoff.

My contribution

Architecture, Python development, Maya integration, validation & render workflow

Toolkit

Python · Maya 2026 · Arnold · PySide6 · OpenImageIO · pytest · JSON · OCIO

Independent pipeline engineering project · version 1.9.0 · August–September 2026

/ OVERVIEW

Catch the failure before the farm does.

A scene can work on an artist's workstation and still fail elsewhere because of missing textures, local paths, incomplete sequences, the wrong camera, unsupported render layers, incompatible Arnold settings or unexpected output names. FarmFlow turns those conditions into explicit checks before render time is spent.

The project evolved from a neutral Python architecture into a working Maya plug-in and dockable panel. It reads the scene without silently repairing it, blocks critical errors, renders Arnold sequences one frame at a time, verifies the generated EXRs and records diagnostics that can be inspected later.

What I built

  • A DCC-neutral core with serializable models for scenes, dependencies, render settings, submissions, jobs and validation results.
  • A Maya 2026 plug-in and dockable PySide6 panel for reading scenes, choosing cameras and frame ranges, validating, rendering and reviewing results.
  • Read-only preflight rules for scene state, textures, references, UDIMs, sequences, output paths, cameras, layers, AOVs, disk space and local constraints.
  • Arnold execution by frame with immediate output verification, safe stopping between frames and restoration of temporary Maya state.
  • OpenImageIO checks for EXR readability, resolution, channels, parts and metadata, with JSON manifests and diagnostics for each run.
  • A persistent local queue, simulated Qube adapter, Nuke handoff generation, OCIO auditing and key, fill and rim light-group AOVs.
01 /

Extract without changing

DCC adapters translate Maya or Houdini scene data into neutral models. The core can then validate most rules in standard Python without importing a DCC.

02 /

Render with restoration

FarmFlow applies the temporary settings required for a selected frame, camera and layer, calls Arnold, verifies the output and restores the previous Maya state even after cancellation or failure.

03 /

Diagnose with evidence

Results record timings, scene snapshots, probable causes and suggested actions. EXRs and JSON reports remain connected to the frame and execution that produced them.

/ PRODUCTION DESIGN

Built around the artist's scene.

Preflight

Errors block execution; warnings remain visible for an informed decision. FarmFlow reports the rule, evidence and a suggested correction without modifying the scene.

Render and verification

Each frame is rendered and checked before the sequence continues. Real output paths reported by Maya are used instead of relying only on expected filename patterns.

Production handoff

Flat render folders, manifests, job state, Arnold statistics, OCIO context and light-group data prepare the result for queueing, diagnosis and compositing.
